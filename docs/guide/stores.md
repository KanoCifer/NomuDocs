# 店铺管理

选哪一国、伙伴代码填什么、用哪个仓库、保修怎么登记、PSKU 序号从几开始，都挂在店铺记录上。一次采集的整批商品共享同一份店铺设置，所以店铺配错了，这一批都会跟着错。

## 哪里看店铺

店铺管理在扩展的设置页里。两个入口：

- 工具栏点 Nomu 图标，弹出 popup，点「打开店铺管理」。
- 按 `Ctrl/⌘ + Shift + P` 唤起操作菜单，进「设置」。

页面上能看到当前激活店铺的概览（国家 / PartnerCode / 仓库 / 保修）、店铺列表，以及「识别当前页」「新建店铺」「编辑」「删除」这些动作。

## 店铺包含哪些字段

| 字段 | 说明 |
| --- | --- |
| 备注 | 用来区分同一个 PartnerCode 下的多条店铺，可以留空 |
| 国家 | `sa`（沙特）或 `ae`（阿联酋） |
| PartnerCode | Noon 的伙伴代码，新建时要以 `PRJ` 开头（后面全是数字）或纯数字，填错存不进去 |
| Noon Store Code | Noon 店铺编码，比如 `STR520747-NSA`，可以手填，也可以一键识别 |
| 履约类型 | `fbp`（卖家自履约）或 `fbn`（Noon 仓） |
| 默认 FBP 仓库 | 新建商品的库存区默认用这个仓库，每件商品还能单独改。要先填好 PartnerCode 才拉得到仓库列表 |
| 保修类型 | 不设置 / 无保修 / 有保修 |
| 保修月数 | 只有选「有保修」时才填，其他类型会被忽略 |
| PSKU 前缀 | PSKU 的固定前缀，默认 `N` |
| PSKU 序号 | 纯数字字符串，见 [PSKU 序号](#psku-序号) |

## 多店铺并存

同一个 PartnerCode 允许多条记录并存，比如同一合作方下既有 `fbp` 又有 `fbn`，或者 UAE、Saudi 各一条。新建永远是追加，不会覆盖老记录；备注填重了会自动加 `-1`、`-2` 这样的后缀。

切换店铺只改「当前激活」这一个指针，商品批次、草稿、任务记录互不打扰。

## 一键识别当前页

打开 noon-catalog 的卖家后台，设置页顶部点「识别当前页」，Nomu 会从当前标签页的 URL 里读出店铺信息并存进店铺记录，存完提示「已识别并保存」并带上识别到的伙伴代码。

店铺信息是从当前标签页地址里读出来的，地址上没有店铺编号就识别不到。

## PSKU 序号

PSKU 序号是纯数字字符串，位宽按你写的来：

- 默认 `1`，填出来就是 `1`、`2`、`3`
- 想保持 `0001` / `0002` 这样的宽度，把序号存成 `0001`
- 超位自然增长，`9999` 之后就变 `10000`

发布时按店铺当前的序号往后递增，用完的号段会记回店铺，同一店铺内不会撞号。

## 履约类型

- `fbp`（Fulfilled by Partner），卖家自履约，自己出仓。走这条要在店铺里选好默认 FBP 仓库，否则每件商品都得自己填仓库和库存。
- `fbn`（Fulfilled by Noon），货入 Noon 仓，由 Noon 配送。这类不写库存。

履约类型挑错的后果是库存没写上，而不是发布直接报错，所以上架后记得去 Noon 后台核对库存。

## 删除与归档

删除店铺会一并清掉它名下的 PSKU 序号等设置，但不会回滚已经发布到 Noon 的商品。Noon 上架是单向动作，删之前先确认没有批次或任务还在用它。

只是暂时不用的话，留着记录改个备注区分就行，多店铺并存本来就是常态。

## 常见问题

### 怎么知道当前激活的是哪家店铺？

popup 顶部直接显示当前店铺的备注、PartnerCode 和国家，设置页里激活的那条会高亮并带一个圆点。

### 同一 PartnerCode 想分两条店铺怎么做？

直接「新建店铺」填同一个 PartnerCode，换个备注或换个国家就行，两条会同时存在，互不影响。

### 改店铺配置会不会影响历史任务？

不会。任务里记的是它跑那一刻的店铺信息，回头改店铺不会回写已经跑过的任务。

### 没看到「识别当前页」按钮？

确认当前打开的是 noon-catalog 后台标签页。如果不是，Nomu 会提示「未检测到当前标签页 URL」；是但没识别出店铺，会提示「当前页面未识别到 project 参数，请打开 noon-catalog」。
