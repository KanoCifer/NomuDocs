# 账户与 AI 积分

Nomu 账户是 Kanocifer 用户系统 v3 的身份。Nomu 工具本身（采集、建图、上架、目录浏览）**不需要登录**——只在调用 AI 能力（翻译、NomuDesign 生图、提示词优化）时才用到 Nomu 账户。

Nomu 账户与你的 Noon 卖家账户完全独立：登录 Nomu 不读取、不影响 Noon 会话。

## 哪些功能需要登录

| 功能 | 需要登录 Nomu | 计费 |
| --- | --- | --- |
| 1688 / noon 源商品采集 | 否 | 免费 |
| 商品图本地合规处理 | 否 | 免费 |
| 上架流水线（product/create → activate） | 否 | 免费 |
| 复制商品 | 否 | 免费 |
| 目录浏览 / 快捷搜索 | 否 | 免费 |
| 实时汇率 | 否 | 免费 |
| AI 翻译（中 → 英 / 阿） | 是 | 消耗积分 |
| NomuDesign 跑图 | 是 | 消耗积分 |
| 提示词 AI 优化 | 是 | 消耗积分 |

未登录或会话过期时翻译、生图与提示词优化不可用；采集、建图与上架**不受影响**。

## 登录方式

打开「账户」扩展页（独立页 `account.html`，入口在 popup / 操作菜单 / 欢迎引导），三段 tab：

- **密码登录** —— 用户名 + 密码
- **注册** —— 用户名 + 邮箱 + 邮箱验证码
- **邮箱魔法链接** —— 输入邮箱 → 后台发送登录链接到邮箱 → 在浏览器点链接确认登录

魔法链接是免密登录的优选：链接里带 `device_id`，浏览器轮询确认登录成功后自动签发会话；轮询有 AbortController 保护，关闭页面就停。

## 会话与多设备

- 登录态存在 `chrome.storage.local` 的 `noonTool.authSession` 键，access token + refresh token 都在本地
- **单会话模型**：在新设备登录会使旧会话失效（后端用 `refresh:<uid>` 固定键，多端互相挤下线）
- 登出立刻清本地 token；插件、账户页、任务面板都会同步退出

## AI 积分卡

账户页第二张卡是「AI 积分」——展示余额 + 最近 10 条消费流水，流水项来源映射：

| 来源 | 含义 |
| --- | --- |
| `translate` | 通用翻译 |
| `nomu_prompt_optimize` | 提示词优化 |
| `design_generate` | NomuDesign 生图 |

- 开页自动拉一次余额与流水
- 余额被并发消耗时以服务端 `402` 为准，本地不预判
- 「刷新」按钮手动重拉
- 余额不足 / 操作过快 / 服务不可用等错误会明确提示

> 详细的数据收集与积分规则见 [隐私政策](/privacy/)。

## 错误码

AI 请求可能抛的错误码（按用户视角）：

| 错误 | 含义 | 建议 |
| --- | --- | --- |
| `auth_required` | 未登录 | 跳账户页登录 |
| `auth_expired` | 登录过期 | 重新登录 |
| `insufficient_credits` | 积分不足 | 联系管理员充值 |

后端返回的错误信息会原样显示在 toast 弹窗里，方便定位问题。

## 幂等与重试扣费

AI 请求带幂等键机制：超时重试不会重复扣费，后端按幂等键去重。所以放心点「重试」——失败的任务在 [任务面板](./tasks) 重试时不会因重试而多扣。

## 常见问题

### 登录后还是提示 `auth_required`？

- 检查 `chrome.storage.local` 的 `noonTool.authSession` 是否被其它扩展或清理工具清掉
- 跨设备登录会把旧会话挤下线——确认是不是在另一台设备登过

### 积分变负数？

余额被并发消耗时以服务端为准，客户端不预判。出现负数大概率是有任务在跑没扣完，刷新一下积分卡即可。

### 怎么注销 Nomu 账户？

账户页登出仅清本地 token；要彻底注销账户，邮件联系管理员。
