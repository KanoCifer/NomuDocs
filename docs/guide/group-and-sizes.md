# 归组与尺寸变体组

上架多件同款不同规格的商品时，Nomu 给你两条路把它们组织在一起发。两条路在 Noon 后台是两个并列的页签，配置位置和限制都不一样：

| 路径 | Noon 后台位置 | 编码特征 | 每件商品 | 典型场景 |
| --- | --- | --- | --- | --- |
| 归组（Group） | Group 页签 | 归组商品编码以 `ZD` 开头 | 每件独立发布，互不连累 | 同款多尺码 / 多型号，颜色系列 |
| 尺寸变体组（Sizes） | Sizes 页签 | 变体父品编码以 `ZA` 开头 | 子品挂在父品下面 | 标准尺码表（衣服 / 鞋） |

不走这两条路的普通单商品上架照旧，不受影响。

## 归组上架（Group）

### 适用场景

同一品牌同一类目的多件商品，每件有自己的 SKU 和图片，但标题、介绍、卖点、类目、部门要保持一致。归组之后买家在前台看到的是一个统一商品页，下方有规格可选。

### 怎么走

在操作菜单里点「创建分组」，走三步：

1. 选一个商品当父商品（组主）
2. 勾选要拉进组的 SKU，同品牌，至少 1 件
3. 填组名、勾规格轴、给每件商品填轴值，确认归组

### 关键规则

- **组内商品必须同品牌**，品牌不一致建不了组。品牌不填的商品能进组，但进组后按组内已有的品牌走。
- **类目不强制一致**，但改组内共享字段时会覆盖所有成员，改之前先想清楚。
- 组内商品必须都属于当前这个店铺。
- 同一件商品不能同时在两个组里，想换组得先从原组移出或解散。
- 组员已经有任务在跑或已完成时，不能直接替换整个组，得先解散重建。
- 组内每件商品各走各的发布流程，一件失败不影响别的件。任务面板里能看到每件的独立状态。
- 组名就是你在建组时填的那个名，后台会按它归拢商品。

### 概念区分

- 归组商品的编码以 `ZD` 开头，出现在 Noon 后台的 Group 页签。
- 变体父品的编码以 `ZA` 开头，出现在 Sizes 页签。
- 这两套机制在 Noon 后台是并列的，不要混着理解。

## 尺寸变体组（Sizes）

### 适用场景

标准尺码表用这条：当前这件商品作为父品，后面挂若干个尺码子品。子品只需要给尺码、SKU 和条码，其余内容跟父品走。

### 怎么走

尺码变体不用单独发任务，直接在单商品上架表单里配：

1. 按[快速上手](./quick-start)抓取或新建商品
2. 打开商品的上架抽屉，滚到「尺码变体」区
3. 在「当前商品 Size」填这件自己的尺码，比如 S / M / L
4. 点「新增 size」逐行加子品，每行填尺码、SKU、条码，SKU 会自动生成，也可以手改
5. 正常提交上架，父品和子品随同一次提交完成

「尺码变体」区留空就是普通单商品发布，不触发任何变体逻辑。

### 关键规则

- **尺码轴只允许 1 个**，就是 Size，不能再挂颜色、款式这些额外轴。
- **父品尺码必填**，填了子品没填父品尺码，这件商品发布时会失败。
- 子品尺码不能和别的子品行重名，重了这条提交不过。
- 父品尺码和某个子品尺码填成一样不会报错，轴选项会自动去重。
- 子品条码可以留空，留空就不写这个条码。
- 父品先发布，再按变体逐个建子品。

### 任务面板标识

尺码变体不是独立任务类型，它跟着单商品上架任务一起跑，任务面板里看到的就是普通单商品任务。子品的编码能在任务详情里看到。

## 选 Group 还是 Sizes？

| 想做的事 | 用什么 |
| --- | --- |
| 标准尺码表（S / M / L / XL …） | **Sizes** |
| 颜色系列（红 / 蓝 / 黑），各色独立商品图 | **Group**，加 Colour Name 轴 |
| 同一型号有多个细分型号（手机 128G / 256G / 512G） | **Group**，加 Model Name 轴 |
| 不同商品图片需要按颜色变体独立展示 | **Group**，加 Colour Name 轴 |
| 子品内容需要跟着父品走 | **Sizes** |

## 常见问题

### 归组了为什么组里商品的状态还是独立的？

归组只是在 Noon 后台把它们摆到一起展示，不是一起成功或一起失败。每件商品走自己的发布流程，任务面板里能逐件看状态。

### 归组要选同品牌吗？

要。同品牌是硬门禁，品牌不一致建不了组。品牌没填的商品能混进来，但它会按组里已有的品牌走。

### 归组和 Sizes 能不能同时存在？

不能。一个商品在单商品表单里挂了尺码变体之后，它的子品就不进归组。归组只能拉还没上架的单商品。

### 尺码变体要单独发一次任务吗？

不用。跟着商品一起提交就行，父品先发布，再按变体逐个建子品。
