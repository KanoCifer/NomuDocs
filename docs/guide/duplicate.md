# 复制商品

「复制商品」帮你在 Noon 平台内做批量搬运：按源 PSKU 找到一件已上架的商品，拉一份完整内容回来，在当前店铺下重建一份新的可上架草稿，类目、品牌、属性、图片都跟着过来，省掉从头填一遍。

典型场景：同款商品要在 UAE、Saudi 双站都上，要把老 PartnerCode 下的爆款搬到新 PartnerCode，或者店铺之间迁品。

> 需要登录 Nomu 账户才能用，未登录时这个页面会换成登录卡。

## 入口

复制入口在 noon-catalog 卖家目录页。操作菜单里点「复制商品」打开批量复制页，也可以从单商品抽屉里对单个商品走复制。

## 输入：源商品定位

每行复制要填三个必填项，外加两个可选项：

| 字段 | 说明 |
| --- | --- |
| 源 PSKU | 复制来源的 Noon PSKU 编码 |
| 目标 PSKU | 新商品在你的店铺里的 Partner SKU |
| Barcode | 可选。留空就沿用源商品的条码 |
| 品牌 | 可选。留空沿用源商品品牌，填了就以本行为准 |

门店、仓库、库存、保修这些不再逐行填，统一走[店铺管理](./stores)，改店铺等于改全局。

## 跨设备复制

复制目标不一定是本机。页面顶部列出你账号下所有已登录的设备，本机在首项，其他设备带「在线 / 离线」角标。选中哪台就在哪台落地：

- **选本机**，复制在本机完成，直接进本机上架队列，不推送任何数据。
- **选其它设备**，本机只把源商品内容推给对方，本机不落库。对方在线就立即接收，离线则等它下次上线自动接收。

两端都要登录同一账号并保持扩展在线。同一个「源 PSKU + 目标 PSKU」已经在跑或已入队时会复用，不会重复入队。

**库存不跟着走**，发送方的库存对接收方没有意义。接收端库存是空的，需要在目标设备的[任务面板](./tasks)里自己填。FBP 没填数量和仓库时，库存这一步会直接跳过，Noon 上就是零库存。

## 单件 vs 批量

单件复制适合临时搬一两个款，批量复制适合店铺初始化和跨店铺迁品。

批量模式下可以直接粘 Excel（制表符分隔）或 CSV（逗号分隔）。列顺序固定：源 PSKU、目标 PSKU、Barcode，第三列可以缺省。粘贴后点「识别粘贴内容」，识别到多少行一目了然，没识别出有效行会直接提示。

行表里每行都能单独改：

- 手动改源 PSKU、目标 PSKU、Barcode
- 一键生成 SKU
- 删除单行

同一批里 Barcode 填重了不行，这些行提交时会判入队失败，并告诉你是跟第几行重复。

## 任务跟踪

复制任务在[任务面板](./tasks)的「复制任务」视图里集中看，状态有五种：

- 等待中，还在排队等处理
- 已入队，复制完成，接下来看上架任务的进度
- 已推送，跨设备复制时对方已收到，本机没落库
- 失败，常见原因是源 PSKU 在 Noon 找不到，或目标 PSKU 在当前店铺已存在
- 已取消

面板提供清空已完成、失败行单独重试、取消在跑任务。

## 复制后能改什么

复制只把可继承的部分拷过来（类目、品牌、属性、图片、介绍等），目标 PSKU、Barcode、库存、仓库、保修按当前店铺配置写入。复制进了上架流程之后，[快速上手](./quick-start)里说的那些上架前编辑都能改。

目标 PSKU 在当前店铺下已经存在时，复制不会覆盖它，而是直接判失败。想换一件商品就换一个目标 PSKU。

## 与归组 / 尺寸变体组的关系

复制出来的是单商品。想把它归到一组，或者挂到尺寸变体组下面，去上架抽屉里走对应流程，见[归组与尺寸变体组](./group-and-sizes)。

## 常见问题

### 复制会覆盖已有商品吗？

不会，目标 PSKU 已存在时这行直接判失败。想覆盖就先在 Noon 后台处理掉旧的那件，或者换个目标 PSKU。

### 类目 / 品牌能复用吗？

类目和品牌都跟随源商品。想换品牌就在批量表格里给这一行填品牌，留空就是跟随源。

### 复制时改类目或品牌后还会跟随源吗？

不会。品牌留空就跟随源商品，填了就以这一行为准。类目始终跟随源商品。

### 复制完看不到商品？

去[任务面板](./tasks)的复制视图看状态。显示已入队就等上架任务跑完，显示失败就看提示里的原因。
